# 卡密授权模块使用说明

给你的脚本加一道"门禁"：客户必须输入你发的卡密才能用，卡密到期自动停用。
纯 Python 标准库，无需安装任何包。

## 文件清单

| 文件 | 作用 | 谁用 |
|---|---|---|
| `licensing.py` | 核心：生成/校验卡密 | 你的脚本 + 发卡工具共用 |
| `gen_key.py` | 发卡工具，生成带有效期的卡密 | **你（卖家）**用 |
| `demo_integration.py` | 接入示例 | 参考 |
| `test_license.py` | 自检脚本 | 改完代码后跑 |

---

## 详细步骤

### 第 1 步：修改密钥（必须做）
打开 `licensing.py`，把顶部的 `SECRET` 改成你自己的随机字符串（32 位以上）：
```python
SECRET = "在这里写一段只有你知道的长随机字符比如a8f3k...9z"
```
**生成端和验证端共用同一个 SECRET**，所以两边（你的发卡工具和客户拿到的脚本）必须一致。
> 警告：别用默认 SECRET，否则别人反编译脚本就能自己造卡密。

### 第 2 步：给客户发卡密
在你自己电脑上运行：
```bash
python gen_key.py 30        # 生成 30 天卡密
python gen_key.py 365       # 生成一年卡密
```
屏幕会输出一串卡密，例如 `eyJl-eHAi-...-b7fb-30d`，把它发给客户。

### 第 3 步：把校验接进你的脚本
在你脚本**最开头**加两行：
```python
from licensing import require_license, SECRET
require_license(SECRET)     # 卡密不对就直接退出，下面代码不会执行
```
把 `licensing.py` 放到你脚本同一个文件夹即可（Python 会自动找到它）。

### 第 4 步：发给客户
把你的脚本 + `licensing.py` 一起打包给客户。客户首次运行时：
- 会提示"请输入卡密"，客户粘贴你发的那串即可
- 之后自动记住，**下次不再需要输入**
- 卡密有效期内：脚本正常跑
- 卡密过期：提示"卡密已于 xxxx-xx-xx 过期"并退出 —— 这就是"自动停用"

### 第 5 步（可选）：长时间运行也要到期停用
如果你的脚本一跑就是好几天，光靠"启动时检查"不够，加一行后台定时复查：
```python
from licensing import start_expiry_watchdog
start_expiry_watchdog(SECRET, interval_sec=3600)  # 每小时复查一次，过期自动退出
```
放在 `require_license()` 之后就行。

## 验证是否做对了
```bash
python test_license.py     # 应显示 全部通过
python demo_integration.py # 会提示输入卡密，输入你发的卡密即可看到"授权成功"
```

## 原理（简单理解）
卡密里藏着两部分：
1. **到期日**（例如 2026-09-09）+ 一个随机 ID，经过编码
2. **签名**：用你的 SECRET 对上面那段算出的校验值

校验时：
- 重新算一遍签名，和卡密里带的签名比对 → 不一致就是假的/被改过
- 读出到期日，和今天比较 → 今天更晚就拒绝

因为签名必须知道 SECRET 才算得对，所以**没有 SECRET 的人没法伪造卡密、也没法把到期日改晚**。

---

## 重要安全说明（务必看）
- 这套是**本地校验**，适合"防君子不防小人"。懂技术的人仍可能改系统时间、或反编译脚本取出 SECRET 后自造卡密。
- 如果你卖的是高价值服务，建议升级成**在线校验**：卡密验证走你的服务器（服务器存着每张卡的状态和到期日，还能随时吊销）。需要的话我可以再帮你做一版带后端 API 的。
- 不要把 SECRET 提交到公开代码仓库。
- 客户机器上的 `.license` 文件存着卡密，重装系统/换电脑会丢失，属正常，重新输入即可。
